Technical blueprint · Sahyog AI

Small pieces, one real flow

A local Streamlit app connects Gemini when configured—or transparent local rules without a key—to a relief-operations dashboard.

Spec approved

How the report moves through the app

If Gemini fails or returns unusable data, validation stops the flow and the UI shows an error instead of a made-up success.

The pieces

Report form · app.py

Collects and validates user input, shows the safety boundary, and starts assessment.

Gemini · sahyog_ai/gemini.py

When configured, sends the report to the model with a structured output request and explicit error handling.

Local rules · sahyog_ai/local_triage.py

When no key is configured, calculates an explicitly labeled code-based estimate; never presents it as AI.

Data checks · sahyog_ai/models.py

Checks score and action steps and records whether a result came from Gemini, local rules, or sample data.

Operations · app.py

Shows reports, filters active/resolved items, updates statuses, and explains the empty state. A no-key preview loads separate sample records that are never presented as Gemini output.

Volunteer sample · app.py

Shows example statuses with clear labels; does not suggest real availability or dispatch.

Safety

AI output and local rule estimates are informational only, not validated triage; the app is not an emergency service and advises contacting local emergency services for immediate danger.

Local start command

Use Python 3.10+, install requirements, set GEMINI_API_KEY locally, then run streamlit run app.py. Open the localhost URL Streamlit prints. Never commit the key; use the same local app for the required demo recording.

Data, costs, and limits

Reports stay in the Streamlit session and disappear when the app restarts. A key enables live Gemini output; without one, the form uses clearly labeled local rules, not AI or validated triage. Sample records are separately labeled examples. Check current pricing and rate limits. No database or hosting service is used.
